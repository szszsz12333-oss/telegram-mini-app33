# Mini App «Відстрочка»

Готовая витрина Telegram Mini App для оформления доступа к боту на 30, 60, 90 или 120 дней. После создания заявки бот отправляет пользователю текущие реквизиты. Администратор вручную проверяет перевод и активирует доступ командой.

## Что хранится

Сервер сохраняет только технические данные, необходимые для доступа: номер заявки, Telegram ID, тариф, статус и дату завершения доступа. Пол, дата рождения, ПІБ, отмеченные основания и фото не отправляются в API и не сохраняются. Фото остаётся локально в браузере и очищается после создания заявки.

> Если понадобится использовать фото или сведения заявника для проверки, потребуется отдельная политика обработки данных и защищённое временное хранилище. Не пересылайте их через `sendData` или команды бота.

## Установка

1. Установите Node.js 20 или новее.
2. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен бота от BotFather;
   - `ADMIN_IDS` — ваш числовой Telegram ID; несколько ID перечисляйте через запятую;
   - `PAYMENT_DETAILS` — актуальные реквизиты, которые бот отправит пользователю;
   - `APP_ORIGIN` — адрес опубликованной Mini App, например `https://name.github.io`.
3. Запустите сервер:

   ```bash
   npm run start
   ```

Зависимостей нет, `npm install` не нужен.

## Размещение

Файлы `index.html` и `config.js` можно разместить на GitHub Pages. В `config.js` впишите HTTPS-адрес развернутого Node-сервера:

```js
window.APP_CONFIG = { apiBaseUrl: 'https://api.example.com' };
```

Сам сервер разместите на платформе с постоянным Node-процессом и HTTPS. Укажите URL страницы в настройках Mini App у BotFather. Сервер использует long polling для команд бота, поэтому не настраивайте webhook одновременно с ним.

Сервер хранит сроки доступа в файле `state.json`, поэтому на хостинге подключите постоянный диск и задайте его путь через `DATA_DIR` (например, `/var/data`). Без постоянного диска заказы и доступы исчезнут после перезапуска или нового развёртывания.

## Команды бота

Команды работают только для ID из `ADMIN_IDS`:

```text
/confirm ORD-...  — подтвердить перевод, продлить доступ и уведомить клиента
/reject ORD-...   — отменить ожидающую заявку
/orders           — показать до 20 ожидающих заявок
```

Пользователь может написать `/status`, чтобы увидеть дату окончания доступа. При повторной покупке новый срок добавляется к текущему, если доступ ещё активен.

Платные обработчики вашего бота должны перед выполнением своей функции проверять `currentAccess(userId)`: при отсутствии активного доступа предлагайте пользователю открыть Mini App. Конкретная платная функция в этот пакет не включена, поскольку её логика не была задана.

## Важные детали

- Токен бота и реквизиты не должны попадать в Git, HTML или `config.js`.
- Проверка `initData` на сервере не позволяет подменять Telegram ID клиента.
- Создание заявки требует открытия страницы из Telegram. В обычном браузере интерфейс можно посмотреть, но заявку создать нельзя.
- Продажа цифрового доступа внутри Telegram через перевод на карту может противоречить правилам Telegram; перед запуском оцените требования платформы и применимое законодательство.
