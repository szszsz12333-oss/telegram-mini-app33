# Mini App «Відстрочка»

Готовая витрина Telegram Mini App для оформления доступа к боту на 30, 60, 90 или 120 дней. После создания заявки бот предлагает выбрать оплату через Crypto или картой; карта в текущей версии помечена как временно недоступная. Выбор Crypto заменяет сообщение выбора на реквизиты, а «Я оплатив(ла)» заменяет его на подтверждение — сообщения не накапливаются в чате. После успешной оплаты система зачисления автоматически активирует доступ.

## Что хранится

Сервер сохраняет данные, необходимые для доступа и связи с клиентом: номер заявки, Telegram ID, имя, фамилию, `@username`, тариф, статус и дату завершения доступа. При первом запуске бота администраторы получают уведомление с общедоступными данными Telegram-профиля клиента: именем, `@username` (если указан) и Telegram ID. Пол, дата рождения, ПІБ, отмеченные основания и фото не отправляются в API и не сохраняются. Фото остаётся локально в браузере и очищается после создания заявки.

> Если понадобится использовать фото или сведения заявника для проверки, потребуется отдельная политика обработки данных и защищённое временное хранилище. Не пересылайте их через `sendData` или команды бота.

## Установка

1. Установите Node.js 20 или новее.
2. Скопируйте `.env.example` в `.env` и заполните:
   - `BOT_TOKEN` — токен бота от BotFather;
   - `ADMIN_IDS` — ваш числовой Telegram ID; несколько ID перечисляйте через запятую;
   - `PAYMENT_DETAILS` — реквизиты карты; в текущем меню карта временно недоступна;
   - `CRYPTO_PAYMENT_DETAILS` — crypto-реквизиты: укажите сеть и адрес, разделяя строки через `\n`;
   - `PAYMENT_WEBHOOK_SECRET` — длинный секретный ключ для вашей системы зачисления;
   - `APP_ORIGIN` — адрес опубликованной Mini App, например `https://name.github.io`.
   - `MINI_APP_URL` — полный HTTPS-адрес страницы Mini App; для текущего развертывания: `https://telegram-mini-app33.onrender.com/`.
   - `SUPPORT_USERNAME` — необязательный username поддержки без `@`.
3. Запустите сервер:

   ```bash
   npm run start
   ```

Зависимостей нет, `npm install` не нужен.

## Размещение

Файлы `index.html` и `config.js` можно разместить на GitHub Pages. В `config.js` впишите HTTPS-адрес развернутого Node-сервера:

```js
window.APP_CONFIG = {
  apiBaseUrl: 'https://api.example.com',
  supportUsername: 'manager_username',
};
```

Сам сервер разместите на платформе с постоянным Node-процессом и HTTPS. Укажите URL страницы в настройках Mini App у BotFather. Сервер использует long polling для команд бота, поэтому не настраивайте webhook одновременно с ним.

Сервер хранит сроки доступа в файле `state.json`, поэтому на хостинге подключите постоянный диск и задайте его путь через `DATA_DIR` (например, `/var/data`). Без постоянного диска заказы и доступы исчезнут после перезапуска или нового развёртывания.

## Автоматическое зачисление

После успешной оплаты ваша система должна отправить серверу запрос:

```http
POST https://api.example.com/api/payments/confirm
Content-Type: application/json
X-Payment-Webhook-Secret: <значение PAYMENT_WEBHOOK_SECRET>

{"orderId":"ORD-..."}
```

Сервер проверяет секрет, помечает заявку как оплаченную, продлевает доступ и отправляет клиенту сообщение в Telegram. Повторный запрос с тем же номером заявки безопасен: срок доступа не будет продлён второй раз.

В сообщении с реквизитами клиент увидит кнопку «Я оплатив(ла)». После её нажатия каждый ID из `ADMIN_IDS` получит уведомление с номером заявки, именем, фамилией, `@username`, Telegram ID, тарифом и суммой. Если уведомление не дошло до одного администратора, повторное нажатие отправит его только тем, кто ещё не получил сообщение. Нажатие кнопки не активирует доступ — его активирует система зачисления или резервная команда администратора.

## Команды бота

Команды работают только для ID из `ADMIN_IDS`:

```text
/confirm ORD-...  — резервно подтвердить перевод, продлить доступ и уведомить клиента
/o ORD-...        — сообщить клиенту, что его платёж находится в обработке
/reject ORD-...   — отменить ожидающую заявку
/orders           — показать до 20 ожидающих заявок
/about            — описание услуги и процесса оформления
/support          — ссылка на поддержку
/profile          — личный профиль: @username, статус доступа и последние заявки
```

Пользователь может написать `/status`, чтобы увидеть дату окончания доступа. При повторной покупке новый срок добавляется к текущему, если доступ ещё активен.

Платные обработчики вашего бота должны перед выполнением своей функции проверять `currentAccess(userId)`: при отсутствии активного доступа предлагайте пользователю открыть Mini App. Конкретная платная функция в этот пакет не включена, поскольку её логика не была задана.

Команда `/start` выводит кнопки «Оформити доступ», «Про послугу», «Особистий профіль» и, если задан `SUPPORT_USERNAME`, «Підтримка». Переходы между «Про послугу», профилем и главным меню заменяют текущее сообщение бота, не создавая новых сообщений в чате.

## Локальное тестирование

Чтобы проверить форму без Telegram, токена и реальной оплаты, локально установите `ALLOW_DEMO_ORDERS=true`, запустите сервер и откройте `http://127.0.0.1:3000/?demo=1`. Такая заявка получает пометку demo: бот не получает реквизиты, платёж не создаётся и доступ не активируется. Никогда не включайте этот параметр в production.

## Важные детали

- Токен бота и реквизиты не должны попадать в Git, HTML или `config.js`.
- Проверка `initData` на сервере не позволяет подменять Telegram ID клиента.
- Создание заявки требует открытия страницы из Telegram. В обычном браузере интерфейс можно посмотреть, но заявку создать нельзя.
- Продажа цифрового доступа внутри Telegram через перевод на карту может противоречить правилам Telegram; перед запуском оцените требования платформы и применимое законодательство.
